# Polite decline

A good decline is short, clear in its first sentence, and kind. It does not over-explain
and it does not leave a door open the user did not want open.

## Steps

1. Read the request in full so the reply answers what was actually asked.
2. Check with the user, if they did not say: is this a firm no, or "not now"? Do they want to
   offer an alternative (someone else, a later date, a smaller version)?
3. Pick the closest pattern from `patterns.md` (load it with `load_skill`, file
   `patterns.md`) and adapt it: their names, the specific thing, the user's usual tone.
4. Reply in the same thread to the same people. For a calendar invitation, use
   `calendar_respond` with a note instead of a separate email.

## Rules

- Say no in the first or second sentence.
- One reason at most, and only if the user gave one. Never invent a reason.
- No false promises ("maybe next time") unless the user means it.
- The user approves the exact text before anything is sent.
